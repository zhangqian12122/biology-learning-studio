# CoRead（共读模式）黑客松升级计划

**开发位置：D 盘独立目录 `D:\co-read-game\，与 biology-learning-studio（生物学习站）完全无关，生物项目零改动。**

## 背景与判断（已确认）

- 知乎黑客松2026·校园新锐季主题："用 AI 重塑下一代知识社区的互动形态"，赛道：社区连接 / 知识生产 / 互动叙事。CoRead 一个产品切三条，**继续这个方向，做混合 AI 升级**。
- 源码现状（zip v1.0.0，79MB）：纯原生 HTML/CSS/JS，`app-v1.js" 3685 行（前 864 行为章节数据），两个完整章节，77MB 自绘像素美术，`node server.js" 零依赖即可跑。**无任何网络调用（AI 是纯脚本）、无存档（纯内存态）**。

## Phase 0 — 移到 D 盘 + 环境搭建（第 1 天）

1. 把微信附件里的 `CoRead-Source-v1.0.0-20260905.zip（目前在 C 盘）解压到 **`D:\co-read-game\**；原 zip 保留不动。
2. 在 D:\co-read-game`git init`，基线 commit。
3. `node server.js 起本地服务（127.0.0.1:4173），浏览器全流程试玩两个章节，确认基线可玩；跑通 `npm test（smoke.mjs）。
4. 向队友要黑客松提供 API 的具体形式（base URL / key / 是否 OpenAI 兼容），期间先按 OpenAI 兼容协议设计适配层。

## Phase 1 — 存档系统（第 1–3 天）

1. localStorage 自动存档：章节进度、伙伴名字、隐藏特质值、选择历史与 echo 快照、当前场景。
2. 关键节点自动写入；启动页提供「继续上次共读 / 重新开始」。

## Phase 2 — AI 基础设施（第 3–5 天）

1. `ai-client.js 适配层：OpenAI 兼容协议，可配置 base URL / key / 模型名；key 只存本地 localStorage。
2. 游戏内设置面板：AI 开关、连接测试。
3. **脚本兜底**：每个 AI 调用点保留现有脚本作为 fallback；断网/超时/无 key 时无缝降级，UI 显示「AI 增强」状态，演示永不翻车。

## Phase 3 — 三个 AI 能力点（第 5–10 天，按价值排序）

1. **伙伴动态反应**：玩家选材料/做决定时，LLM 以 00 的口吻生成实时独白（注入当前特质值与情绪状态），输出 JSON 映射到现有 5 种情绪立绘；兜底用现有脚本。
2. **档案 02 · 自选问题共读（核心卖点 demo）**：玩家粘贴任意知乎问题，LLM 结构化为可玩档案（4 份带作者/日期/来源标注的材料、决定点、草稿开头，标注“模拟演绎”），走正常章节流程、伙伴全程动态对话；JSON 校验 + 失败重试 + 内置示例兜底。
3. **共写回答助手**：草稿工坊中 LLM 额外生成一条 00 风格的回答开头建议（原 3 条脚本开头保留），玩家仍拍板。

## Phase 4 — 清理与打磨（第 10–13 天）

1. 美术瘦身：删除同精灵图的废弃版本（v1–v5 中未引用的），预期砍几十 MB。
2. 结尾卡片加立意陈述；首次上手流程顺一遍。
3. Stretch goal：手写第三章。

## Phase 5 — 提交物料（第 13–14 天 +）

1. 3 分钟演示视频；README 重写（评委视角）；知乎发布图文。
2. 部署更新到 coread.dihaolab.cn（默认脚本模式，AI 模式按黑客松 API 形式决定部署方式）。
3. 最终 QA：扩展 smoke.mjs 覆盖存档与 AI 降级路径，浏览器全流程回归。

## 验证方式

每个 Phase 结束跑 smoke.mjs + 浏览器试玩关键路径；AI 功能验证真实调用与断网兜底两条路径；提交前浏览器+Electron 双端走查。
